## AutoHarness: what was actually inspected

Upstream: https://github.com/tigerless-labs/autoharness, commit `27d13c1d8091681db05a10ef9626081217da240f`.

The upstream reflector proposes changes from an episode, compares against existing skills, cites raw evidence and separates proposal from deterministic promotion. Its host hooks provide recall and its lifecycle uses usage/view counters and probation/capacity policies. It is a Claude Code plugin, not an HTTP inference model, hosted marketing backend or automatically safe shared-tenant service. No upstream daemon, filesystem hooks, global `.claude/skills` directory or unrestricted script tool was installed on the product worker.

## Working path in this increment

Approved copy corrections → tenant/channel-scoped evidence fingerprints → proposed rule → explicit activation → current-evidence check → shared copy harness → OpenAI **or explicitly enabled Claude** → output rule validation → saved provenance. Expired/edited/deleted evidence stops recall. Rules can be retired; source packs stay immutable. No paid reflection call is used.

This path covers **no hashtags, no emoji and captions of at most 80 words**, each supported by two distinct corrected creatives. It does not constitute general semantic skill distillation. The same context is built before provider routing. Default reasoning remains OpenAI; optional Claude requires its key, allowlist, verified rate card and live acceptance. Never infer Claude execution from the existence of an adapter.

Existing observational performance experiments are separate and reversible. Their evidence is revalidated before recall; non-randomized results are not proven causation or universal brand preferences. Image and footage prompts load the selected specialist references and confirmed brand fields, but **general learned visual/video procedures are not yet recalled across those generation workflows**.

## Central system still required to meet the original request

Update, 20 October: the v53 increment implements bounded reasoning-provider reflection, exact-source proposals, explicit activation/replacement/retirement and task/channel-specific recall for copy and written image/video direction. See CREATIVE-PROCEDURES.md. The following original gap list remains a scope reference, not a claim that these newly implemented pieces are still absent. Rendered-media interpretation, automatic semantic evaluation and measured creative improvement remain unverified or unimplemented.

1. A generic, bounded reflection job over redacted review/production episodes; use the approved reasoning provider, existing spend reservation and no automatic retry after uncertain calls.
2. Structured skill proposals with scenario/trigger, reusable instruction, exact evidence, limitations and expected checks—not unrestricted executable files or copied transcripts.
3. Business-scoped, immutable skill revisions and explicit merge/supersession links; reconcile contradictory lessons. Never overwrite supplied source packs or share client learning globally by default.
4. The app-owned task-aware graph assembler now freezes and revalidates scoped knowledge for copy, imagery and video; weekly briefs retain planning snapshots. General learned visual/strategic procedures, semantic conflict resolution and historical snapshot erasure policy remain beyond this bounded implementation. See BUSINESS-KNOWLEDGE.md.
5. Recorded exposure, application, rejection and observed outcomes. Distinguish model compliance, customer preference and marketing effectiveness. Evaluate and roll back promotions; usage alone is not creative quality.
6. Application-owned tool registry and finite workflow execution for each imported specialist; sandbox any new renderer, prohibit arbitrary shell/network access and avoid forwarding customer assets to unapproved proxies.
7. Cross-provider, cross-business and adversarial end-to-end acceptance, including feedback that is not one of the three deterministic rules and real visual revisions.

These are central product requirements, not optional polish. This release is useful incremental work, but is **not completion of the full AutoHarness-style system or all supplied tools**. API credentials alone cannot close these gaps.

## Graphiti decision — explicitly excluded

Reviewed the official [Graphiti repository](https://github.com/getzep/graphiti). Its temporal knowledge graph can connect episodes, facts and their validity over time. It requires a supported graph database and an inference/embedding pipeline; it is not a drop-in PostgreSQL feature and does not itself evaluate or promote marketing skills. No Graphiti runtime, graph service or additional paid extraction was enabled in this release.

The user's subsequent direction excludes Graphiti entirely. The app-owned graph projection uses existing PostgreSQL relationships and persists exact task snapshots without a second datastore. Retrieved relationships remain evidence, not automatically approved instructions. Proposed skills still require evaluation and approval. See BUSINESS-KNOWLEDGE.md for the implemented connections, recall, invalidation and explicit limitations.
