# Private storage acceptance

`npm run test:e2e:storage` runs the browser suite with isolated, real S3-compatible storage instead of skipping private uploads. Build the app first; provide matching `DATABASE_URL` and `TEST_DATABASE_URL` pointing to a disposable localhost PostgreSQL database with migrations applied. Docker, OpenSSL, Node 26 and Chrome are required. Set `TEST_FFMPEG_PATH`/`TEST_FFPROBE_PATH` for media journeys. Do not run unit/database tests concurrently against the browser database.

The runner starts the official SeaweedFS 4.48 image pinned by multi-architecture digest. It uses a non-root process, read-only root filesystem, bounded temporary memory filesystems, 512 MiB/one-CPU limits, dropped capabilities, no host data mount and a dynamically allocated loopback-only S3 port. Admin and other service ports are not published; optional services and telemetry are disabled. A temporary localhost HTTPS proxy preserves signed requests and streams bytes to this fixture; it does not implement or fake storage responses.

Only this run's self-signed certificate is added to the child Node trust store. TLS verification remains enabled, and an explicitly untrusted connection must fail. New random bucket/credentials are scoped to the fixture. Provider credentials and execution flags are not inherited. Local application `.env` files cause refusal before creating resources because Next can load them outside the child environment. This does not modify Railway, system certificate stores or production storage settings.

Before browser tests, the actual application S3 adapter must pass round-trips for five supported media content types, exact metadata, private/no-store responses, anonymous and invalid-signature denial, bounded reads, sequential and concurrent immutable writes, deletion and missing-object responses. These are transport checks, not assertions that synthetic bytes are valid video/audio. The browser case separately exercises a genuine image upload/re-encode, preview, approval, cross-tenant denial, archive/restore and restricted viewer permissions.

The runner removes only its uniquely named, label-verified container and its own temporary certificate directory, including on ordinary failure or interruption. Abrupt host shutdown or SIGKILL cannot run cleanup; inspect exact `marketingbus.storage-fixture` labels before removing any orphan, never prune unrelated containers. A missing Docker daemon/image/network or failed storage assertion fails CI; there is no fallback mock or automatic skip.

Initial harness trials exposed a host bind-mount incompatibility and a candidate Garage backend accepting an immutable overwrite. Neither production transport nor acceptance assertions were relaxed. The final SeaweedFS fixture uses no host mount; writable data paths are temporary mounts. Live Railway bucket policy, conditional-write semantics, region/network behavior, retention and disaster recovery still require their own acceptance evidence. Passing this suite is **not** production object-restoration or scale verification.

Reference implementation: [SeaweedFS 4.48](https://github.com/seaweedfs/seaweedfs/tree/4.48), including its mini server and conditional-write handlers. No production dependency or hosting service is added.
