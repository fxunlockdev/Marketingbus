# Social access lifecycle

An elapsed saved token expiry blocks publishing and account/metric reads at execution time. Runtime `studio-v48-social-access-lifecycle` additionally removes expired local credentials and cached account data in the existing maintenance group, one account per tick, even with all paid/social execution disabled. Migration 54 adds the `(status, expiresAt)` lookup index; it changes no existing grants or publication data.

The worker locks the owning business and rechecks the exact authorization version and expiry before committing. A newer grant wins over a stale candidate. Concurrent workers cannot consume the same grant twice. A busy business is skipped for the current tick; the queue monitor reports expiries still overdue beyond its configured threshold. Background cleanup is not an exact-time SLA; existing request-time access checks remain authoritative.

Cleanup increments the grant version, sets `RECONNECT_REQUIRED`, removes ciphertext/permissions/expiry/current account snapshot and read leases, cancels queued posts, and stops metric polling. Submitted or uncertain posts stay uncertain, with their leases, upload identity, candidate receipt and submission fence intact. Published receipts, historical metrics and audit remain. In-flight HTTP and remote network copies cannot be recalled. Cleanup is local, not remote grant revocation, a data-deletion callback, or deletion from backups.

Fresh OAuth renewal flows survive natural expiry and still undergo their own expiry/session/scope checks. Explicit disconnection and a publishing adapter's definitive `TOKEN_REVOKED` result cancel pending same-provider flows. Generic network/permission errors are not reclassified as confirmed revocation. Existing transport preflight verification remains required. No refresh token is fabricated and no unsupported automatic renewal request is sent.

Connections shows an expiry warning within seven days, a labelled renewal/reconnect action and the same explicit account-choice OAuth flow. Disabled platforms and viewer roles cannot reconnect. A renewed grant does not resurrect cancelled schedules, restart uncertain lookups, or resume stopped metrics. Owners/admins must schedule again where permitted; immutable submitted attempts cannot be resent. Operators can resume read-only uncertain receipt lookup through the existing audited procedure after validating the renewed account; stopped metric recovery remains a separate guarded action. Selecting a different network account creates that account's connection rather than silently moving old posts.

The read-only operator queue report includes overdue cleanup and `ACCESS_RENEWAL_REQUIRED` rows. It emits no tokens, account labels, external identifiers or provider responses and never reconnects or retries work.

Verification uses local PostgreSQL, the actual disabled worker process, controlled provider fixtures, actual browser routes, access-control checks and synthetic restoration. It does not prove live provider expiry/revocation delivery. Remote deauthorization callbacks, provider-specific automatic refresh where supported, app approval and designated-account acceptance remain separate unfinished work.
